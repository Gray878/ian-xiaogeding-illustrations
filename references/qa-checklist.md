# 小鸽钉单核叙事：QA Checklist

## 必过项

- 已锁定为小鸽钉单核叙事，不是知识拼贴。
- 是 16:9 横版。
- 背景是干净白底。
- 主体或小鸽钉有一块清晰的主色平涂，至多一个关键物件使用辅色；不是黑白线稿加少量彩色箭头，也不是全物件上色。
- 使用 2–3 个集中颜色，主色、辅色与风险色有明确分工，没有彩虹色或荧光色。
- 有小鸽钉。
- 实际生成调用附加了 `assets/examples/18-xiaogeding-colorful-pipeline-repair.png` 或用户指定的角色设定图；只写路径或文字描述不算。
- 小鸽钉保持固定连续头身轮廓、浅雾蓝主体、豆眼、短橙嘴、细腿、短翅和芥黄色矩形斜挎包。
- 小鸽钉承担核心动作，不只是装饰。
- 没有复刻旧案例构图，而是为当前文章生成了新隐喻。
- 画面怪诞、有创意、有意思。
- 简洁清爽，主体不超过画面约 60%。
- 一张图只讲一个核心结构。
- 中文标注少、短、能读。
- 橙色只用于主路径或箭头。
- 红色只用于重点、问题、提醒或结果。
- 蓝色只用于补充说明、反馈或系统状态。
- 若 `material-plan.json` 为本场景选择了本地素材，素材以独立贴图层清晰出现，并与小鸽钉动作共同服务一个命题。
- 两张及以上配图或任何视频已保存 `character-reference.json`，并把基准图与所有角色层按同一可视高度排成 contact sheet；每个场景的参考图调用状态与 `generationMode` 一致，`identitySourceVerified` 和 `identityQa` 均通过。

## 失败信号

出现以下情况，重生成或局部编辑：

- 左上角有“常见坑 / Workflow / 系统架构图 / 路线图”等标题。
- 小鸽钉像宠物、吉祥物、表情包、写实鸟或可爱卡通。
- 不同画面中的小鸽钉出现独立圆头、矮胖团子、细长豆形、紫色/深蓝主体、灰包、工具杯替代斜挎包、眼嘴比例突变等身份漂移。
- 多场景分别使用纯文字整图生成，未真实传入基准图，或只以上一张生成结果串联下一张。
- 画面像 PPT、课程课件、正式流程图。
- 元素太多、箭头太多、节点太多。
- 文字变成大段解释。
- 背景有纸纹、阴影、渐变、米色、噪点。
- 图像模型生成的假 UI、假截图或科技感界面。经过素材审计的真实文档/图表局部贴图不属于此失败项。
- 已有相关可发布素材却完全未使用，或只缩成不可辨认的装饰。
- 中文错字严重或标注不可读。
- 画面太死板，没有荒诞隐喻。
- 和当前参考图或归档旧案例构图过于相似。

## 迭代方法

- 太普通：让小鸽钉成为动作主体，加入一个奇怪但成立的隐喻。
- 太复杂：删节点，只保留一个动作和 3-5 个短标注。
- 太可爱：强调 deadpan、blank serious expression、not cute、not mascot。
- 身份漂移：保留场景和主物件，只使用基准图重新生成或编辑独立角色层；每次仍同时传入基准图，不用上一场输出替代基准图。
- 太黑白：让主物件或小鸽钉主体出现一块干净的主色平涂，再给一个工具或第二物件补辅色。
- 太复杂：删除机器零件、排线和材质；让小鸽钉、一个主物件和最多两个支撑物承担全部意思。
- 太 PPT：去掉标题、边框、整齐网格和过多箭头，改成手绘场景。
- 太像旧案例：保留核心意思，换掉主物件和小鸽钉动作。
- 文字错：优先局部编辑；错得多就重生成并减少标注数量。

## 交付判断

高质量图应该让读者先觉得“有点怪”，然后 1 秒内看懂结构。

如果第一眼像教程页、复杂产品草图或机械渲染，而不是白纸上的极简资讯手绘卡，就不合格。
