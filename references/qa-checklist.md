# 小鸽钉单核叙事：QA Checklist

## 必过项

- 已锁定为小鸽钉单核叙事，不是知识拼贴。
- 是 16:9 横版。
- 背景是干净白底。
- 主体或小鸽钉有一块清晰的主色平涂，至多一个关键物件使用辅色；不是黑白线稿加少量彩色箭头，也不是全物件上色。
- 使用 2–3 个集中颜色，主色、辅色与风险色有明确分工，没有彩虹色或荧光色。
- 有小鸽钉。
- 小鸽钉承担核心动作，不只是装饰。
- 没有复刻旧案例构图，而是为当前文章生成了新隐喻。
- 画面怪诞、有创意、有意思。
- 简洁清爽，主体不超过画面约 60%。
- 一张图只讲一个核心结构。
- 中文标注少、短、能读。
- 橙色只用于主路径或箭头。
- 红色只用于重点、问题、提醒或结果。
- 蓝色只用于补充说明、反馈或系统状态。

## 失败信号

出现以下情况，重生成或局部编辑：

- 左上角有“常见坑 / Workflow / 系统架构图 / 路线图”等标题。
- 小鸽钉像宠物、吉祥物、表情包、写实鸟或可爱卡通。
- 画面像 PPT、课程课件、正式流程图。
- 元素太多、箭头太多、节点太多。
- 文字变成大段解释。
- 背景有纸纹、阴影、渐变、米色、噪点。
- 真实 UI 截图或科技感界面。
- 中文错字严重或标注不可读。
- 画面太死板，没有荒诞隐喻。
- 和当前参考图或归档旧案例构图过于相似。

## 迭代方法

- 太普通：让小鸽钉成为动作主体，加入一个奇怪但成立的隐喻。
- 太复杂：删节点，只保留一个动作和 3-5 个短标注。
- 太可爱：强调 deadpan、blank serious expression、not cute、not mascot。
- 太黑白：让主物件或小鸽钉主体出现一块干净的主色平涂，再给一个工具或第二物件补辅色。
- 太复杂：删除机器零件、排线和材质；让小鸽钉、一个主物件和最多两个支撑物承担全部意思。
- 太 PPT：去掉标题、边框、整齐网格和过多箭头，改成手绘场景。
- 太像旧案例：保留核心意思，换掉主物件和小鸽钉动作。
- 文字错：优先局部编辑；错得多就重生成并减少标注数量。

## 交付判断

高质量图应该让读者先觉得“有点怪”，然后 1 秒内看懂结构。

如果第一眼像教程页、复杂产品草图或机械渲染，而不是白纸上的极简资讯手绘卡，就不合格。
