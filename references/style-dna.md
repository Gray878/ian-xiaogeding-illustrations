# 共享风格 DNA

## 一句话

白底、极简、扁平手绘、少量彩色、留白大、资讯卡片感。先看到一个大而简单的中心符号，再发现四周稀疏的提问、数据、人物反应或警示。

## 画面骨架

- 使用 16:9 横版和纯白背景；有效视觉内容通常只占画面 25%–45%，留下大块安静白空间。
- 每张图只放一个平面中心锚点和 3–6 个小卫星；中心锚点可以是圆形、大符号、简单物件或概念字，不要是复杂机器。
- 使用简洁的 2D 平涂和细黑轮廓。轮廓干净、略有人手感，但不要密集排线、素描明暗、厚涂、3D 透视或材质细节。
- 让每个卫星像一个独立、可一眼认出的“小符号”：一个警告牌、一个问号、一个人物姿态、一个小物件或一句短标签；不要把卫星继续展开成场景。
- 人物使用几笔即可读的成人感简笔速写，衣物最多一小块填色；不要真人肖像、卡通头身比或复杂五官。
- 每张图只服务一个视觉命题；知识拼贴可以有多个卫星，但只能有一个中心命题。

## 色彩行为

- 从 `color-system.md` 选择 2–3 个核心色，必要时才加入第 4 个语义色。颜色总面积通常占画面 15%–30%，集中在中心锚点和最关键的 1–2 个卫星。
- 让主色形成一块清晰的平面视觉重心，例如橙色圆、红色警示形或蓝色衣物；不要给每一个物件都上色。
- 保留黑色/深灰为文字、细线和问号；保留白色为空间，而不是把所有形状填满。
- 使用纯色或极轻的手绘不齐边缘；不要渐变、反光、高光、阴影、排线明暗、金属质感、霓虹光或大面积纯黑。

## 文字规则

- 让图像承担解释，标签只做锚定；优先 2–8 个字的短标签。
- 将必须逐字准确的数字、专有名词和结论视为排版元素，而不是让图像模型猜写。
- 静态图需要准确文字时，预留干净白底标签区并用确定性文字层补上；视频用 HTML 字幕或标签层。
- 不在左上角添加“Workflow / 流程图 / 系统架构图 / 常见坑 / 路线图”等类型标题。

## 绝对不要

- 不要复杂机器、满屏物件、细小零件、真实产品渲染、体积透视、素描排线或 3D 质感。
- 不要大面积彩色填满所有物件，也不要黑白线稿加一两处无意义点缀色。
- 不要商业插画、精致扁平插画、真实 UI、科技感界面、密集课程课件、整齐卡片网格、表格或正式流程图。
- 不要渐变、阴影、纸纹、荧光色、彩虹配色、儿童插画、可爱吉祥物海报或无意义装饰角色。

知识拼贴允许多个小图标、简笔人物和短标签；它不是被禁止的“PPT 信息图”。判断标准是：画面是否像一个中心明确、留白充足、色彩集中且可自由扫读的手绘资讯卡。
